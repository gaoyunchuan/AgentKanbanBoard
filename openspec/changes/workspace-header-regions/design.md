## Context

WorkspaceHeader 当前独占一行，RightDock 自带第二行标签并包含 Inspector。panel 同时承担工具类型和属性选择，混淆了两个区域。用户已通过三张参考图明确顶部位置、区域归属和默认展开规则。

## Goals / Non-Goals

目标：顶部只有一个工作区顶栏，中间操作只影响会话/任务，右侧操作只影响工具。会话属性默认收起，任务树属性固定显示，工具可随时收起且资源保持。

不加入新的编辑器写入、执行能力、权限或持久化格式；不改动任务业务执行。

## Decisions

### 布局

采用现有 React 顶栏中的三个独立区域：导航控制、中间业务标题与按钮、右侧工具宿主。RightDock 将自身标签与操作通过 React portal 渲染到右侧顶栏宿主，内容保留在原资源拥有者中。顶栏与内容共用宽度规则，避免复制标签状态。

中间保留提取结果、新会话和会话属性按钮。工具快捷入口、新建标签和收起/展开在右段；任务详情不再是工具标签。右栏收起时保留工具入口及恢复按钮，标签和资源只隐藏、不销毁。

备选为将标签状态全部提升到 ChatApp，会扩大跨组件状态耦合；另一方案把第二行做成视觉上移，无法保证真实顶栏区域对齐且易遮盖原生网页。采用 portal 仅改变展示位置，保持资源生命周期。

### 属性

Inspector 从 RightDock 拆出，作为中间区域的稳定子组件。会话中定位在中间区域顶部，展开后形成有边界、可滚动的面板；默认隐藏，可用同一顶栏按钮或面板关闭按钮收起。任务树中显示为固定属性区，不提供收起按钮。

属性页签与工具选中项独立；提取结果或查看结果只打开中间属性，不改变右侧工具。切换会话默认收起属性，收起本身保留编辑草稿。任务树选任务仍保留已选属性页签。

### 响应式与资源

右侧顶栏和内容共用宽度、最小宽度及可用空间上限；保留拖动调宽。狭窄中间区域中任务树与固定属性上下排列，二者都可操作。标签可横向滚动，顶栏按钮保持可达。原生网页随占位尺寸和窗口变化同步；属性面板限制在中间区域内。

## Risks / Trade-offs

1. 将标签搬到顶栏导致内容分界错位：两处使用同一宽度样式和 CSS 可用空间约束，实际测量顶栏/内容边界。
2. 收起右栏意外销毁 Shell 或文件选择：保持 RightDock 资源实例挂载，仅改变可见性；交互回归检查恢复同一终端和文件标签。
3. 属性与工具仍互相抢选中项：删除 RightDock 的详情分支，单独保存属性页签/展开状态；验证提取结果、工具切换和任务树定位。

## Migration Plan

第一批完成区域拆分与行为回归；第二批完成宽窄布局、原生浏览器和安装验证。复用已安装且摘要一致的 sidecar，不为纯前端改动重新编译 Rust。保留应用备份，安装验证后清理 dist、暂存 UI、打包目录和临时 target。
