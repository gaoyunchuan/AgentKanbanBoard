## Context

用户已确认绑定、历史展示与接续一起完成。现有恢复能读取原 Thread、恢复归档、resume，但只接受已有人工会话。会话表已有 Thread 唯一索引。正式 Codex 二进制支持 thread/list 与 thread/items/list 的游标分页。

## Goals / Non-Goals

保持原 Thread、原目录和唯一归属；列表/历史不进入轮询主链路。绑定不执行模型，恢复成功后由用户明确发送。不自动归档、不抢占写锁、不复制完整历史到 SQLite，不更改任务状态。

## Decisions

- 用户选择完整接续方案；仅建立外部跳转无法满足在本应用继续，复制成新 Thread 会丢失原会话身份，均不采用。
- `codex_conversations.rs` 封装只读列表、元信息、分页历史与绑定仓储；`WorkService::call` 在 actor 外执行只读协议，actor 内复核目标和写入。读取使用最多两个独立 app-server、每个总期限 60 秒，超大响应只终止读取进程，不影响执行连接。列表与条目每页 40，不扫描本机全部 rollout。现场验证发现旧本地后端没有 items/list，回退到独立连接的 thread/read(includeTurns)，由既有 16MiB 单帧上限约束，并对结果提供本地游标分页；超限明确提示在 Codex 查看。
- 新表 `chat_codex_bindings` 只保留 conversation_id 与 ready 标记，历史从 Codex 按需读。现有绑定同任务返回原会话，跨任务拒绝并提示所属任务，已删除记录要求先恢复；不静默迁移。绑定事务创建人工会话，采用原目录、目标任务权限与匹配项目，不继承 Codex 的更高权限。
- 待交接会话在前后端均禁止发送和结果提取；复用恢复弹窗，只有恢复成功后将 ready 置真。运行中/子 Agent/缺失目录/已结束任务拒绝新绑定。归档状态可作为候选，仍由用户明确执行恢复。
- `CodexHistory` 独立按页展示旧消息与可展开工具，稳定 item ID 去重；过滤本应用已记录的 turn，避免新回复重复。页面最多保留 800 条实际记录，空页不消耗展示容量；单项文本限制 16KiB，达到限制提示去 Codex 查看。刷新重新读取最新一页，取消、切换会话、迟到读取不能串入其他目标。
- 显式提取时捕获原历史与本地事件，最多扫描 20 页、总来源不超过 600,000 字节，超限拒绝而不静默遗漏。来源与任务版本、本地事件边界及历史哈希一起冻结；复核后沿用现有隔离总结流程保存提取快照。普通绑定、阅读不持久复制历史。

## Risks / Trade-offs

- Codex 仍持写锁 → 展示待交接，用户归档后可重试，不停止其他进程。
- 历史大或重复 → 分页、文本/页数上限、按 item ID 去重与本地 turn 过滤；不持久复制历史。
- 目录或任务在读取期间变化 → actor 重新检查任务存在、状态、目录排除与唯一归属；原目录不随任务默认项目移动。

## Migration Plan

新增幂等表，保持旧会话与数据不变。完成测试和 review 后构建 Electron，检查草稿及运行任务，正常退出、独立备份安装、重启并在安装副本验收，最后清理可重建制品。回退可使用旧 APP 备份，保留数据库及浏览器状态。
