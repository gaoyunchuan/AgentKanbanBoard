## Context

用户明确选择半自动归档。独立 RPC 归档被 active writer 拒绝，Codex 应用工具通道有签名客户端限制，不采用绕过、界面自动化或终止进程。既有应用共用一个 CodexRuntime。

## Goals / Non-Goals

恢复原 Thread 连接，不发送 Turn，不复制历史，不改变任务状态；只允许空闲、未关闭、无资源占用且目标版本一致的会话。

## Decisions

- 双入口共用恢复弹窗，打开时冻结 conversation_id/thread_id/revision；第一步通过后端验证和现有 Codex 深链打开。
- 确认手动归档后读取 Thread 路径，仅归档路径调用 unarchive，再 resume。未归档但已释放占用也可直接恢复，失败允许重试。
- 恢复在有界后台线程执行，actor 保留最多两个临时恢复占用，禁止目标变更并保持目录排他；其他目录执行和只读轮询可继续。结束再检查连接与目标版本，成功才清理会话连接错误。
- 写锁拒绝属于启动前确定性失败，不 shutdown 共享进程；其他无法判断的恢复错误沿用保守断开行为。

## Risks / Trade-offs

- 归档后恢复失败 → 保留阶段错误，重试通过路径判断跳过已完成恢复。
- 原生 Goal 续跑 → 恢复后沿用暂停 Goal 校验，不调用 turn/start。
- 旧历史内容未同步 → 明确告知只恢复连接，Codex 中新增内容暂不自动导入。

## Migration Plan

不改数据库结构。完成测试后本机构建、签名、正常退出、备份安装、重启与原生验收。
