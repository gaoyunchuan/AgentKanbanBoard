## Context

现有 `RightDock` 只保存工具类型；浏览器自己管理第二层网页标签。`UtilityPanel` 把一次性命令执行与文件目录混放，前端切换页面会重新挂载部分状态。Electron WebContentsView 独立于 React，隐藏 DOM 不会自动隐藏网页。

当前后端的手动命令必须通过调度 actor 领取目录租约，同目录另一个手动命令或 Agent 会被阻止。Codex app-server 现有协议已支持 `command/exec` 的 PTY、持续 stdin、resize 与 terminate，无需另起绕开沙箱的本机 Shell 执行通道。

## Goals / Non-Goals

**Goals:**

- 单一右栏标签模型，对资源实例管理激活、关闭、去重与状态。
- 文件页展示真实项目数据，保留当前文件与目录展开状态。
- 终端为真实持续 Shell，每个标签拥有独立进程、输入和输出，并使用创建时的项目目录与任务沙箱。
- 保留任务详情、浏览器登录状态以及本轮未提交改动。

**Non-Goals:**

- 不在本轮加入编辑器保存、批量重命名、Git 提交等用户未要求的文件写入功能。
- 不复制截图中的侧聊、标注等其它工具。
- 不改变任务执行权限，不把人工终端输出作为 Agent 交付或完成信号。

## Decisions

### 1. 标签以资源实例组织

选用共用标签状态，标签包含稳定 ID、类型、归属会话/项目和标题。网页 ID 使用真实 target ID；文件和变更各为单例工具；终端 ID 使用独立后端会话 ID。标签条位于右侧区域顶端，提供加号工具入口，沿用现有统一窗口 header。

沿用已有浏览器的会话隔离：每个会话保留自己的右栏标签集合，没有会话时按当前任务归属；文件与变更的单例指当前集合中最多各一个。切任务展示对应集合，返回原任务恢复原标签与选中项。隐藏集合的终端继续存活，仍绑定创建时的项目目录，不能被当前项目复用或重新标记；终端数量限制对整个应用计算。

备选方案为保留浏览器内层标签，仅拆文件与终端；会继续产生两层切换，与用户明确要求不符。另一个方案将全部状态塞入一个 panel 字符串，会丢失多实例身份与关闭语义，故不采用。

### 2. 浏览器继续只有一个控制器

浏览器状态和操作提升到右栏控制器，网页逐个投影为右侧标签，不为每个网页启动独立轮询或浏览器连接。用户切网页时激活对应 target；Agent 创建/关闭网页同步标签集合。切到其它工具、隐藏右栏或切换会话时，明确隐藏原生 view；状态更新不能在后台重新把网页盖到文件/终端上。

关闭网页标签实际关闭对应 target，最后一个网页关闭后不留下失效选中项。保留登录 partition，不把关闭标签解释为清除登录数据。

### 3. 文件页为单例工作区

右侧为懒加载目录树，支持展开、筛选和文件选中；左侧为当前文件内容（文本/图片与不可预览状态）。上方显示当前路径及目录树开关。再次点击文件入口聚焦原页面，点击目录内其它文件在同一个文件工具内更换内容。

缓存按项目/会话归属区分；读取请求用序号和归属校验，旧异步结果不能覆盖新项目。目录不全盘扫描，单文件预览有大小上限，过大或二进制返回明确提示。

### 4. 终端复用 app-server PTY

后端维护独立终端 registry。创建时解析有效当前项目目录，使用 `command/exec` 启动交互 Shell，注册后异步接收输出；write/resize/close 只允许操作 registry 中该归属下的进程。终端前端使用成熟的终端渲染组件，避免自己模拟光标、控制码与 Shell 行编辑。

前端切标签只切可见性，不重建 Shell；关闭标签等待后端终止，失败保留可恢复的关闭状态。应用退出统一清理，断线终端明确显示断开，不假装原 Shell 已恢复。

建议首轮上限为应用内 8 个终端，输出环形缓冲每个最多 1 MiB，前端滚动历史有固定行数，stdin 单次最多 16 KiB；达到限制明确提示，不静默丢弃已有终端。每个 PTY 事件不逐字符追加 SQLite 长期历史，避免无界输出增长。

备选方案为继续使用一次性命令表单，不能保留 cd、环境和交互输入，不符合截图及“新建终端”的使用目标。直接在 Electron 启动无沙箱进程会改变权限边界，因此不采用。

### 5. 用户已确定的执行规则

项目目录互斥只约束 Agent。浏览器、文件和所有人工终端均可并发，不占 Agent 并发额度。手动终端启动/存活不得加入调度器的目录占用集合，也不能因为 Agent 正在使用目录而拒绝启动。保留 Agent 与 Agent 之间的串行检查。

该选择已由用户直接明确，覆盖此前手动命令与 Agent 互斥的旧规则。终端仍遵循所绑定任务的沙箱，不因并行而提升权限。界面展示目录即可，不再增加互斥保护或确认流程。

## Risks / Trade-offs

1. 原生网页可能覆盖其它标签 → 原生 view 的显示权由当前活动标签决定；Agent 侧状态更新与页面激活不得绕过此规则，使用真实 Electron 验收。
2. 隐藏或切项目导致文件、终端状态错位 → 稳定资源 ID、固定项目归属、异步序号校验及状态提升；多项目切换和迟到返回回归。
3. 持续终端形成残留进程和无限输出 → 后端拥有清理责任、数量与缓冲上限、退出清理；测试关闭单终端不影响其它终端及失败状态不被吞掉。

## Migration Plan

分两批交付：先完成标签管理、浏览器逐页标签和文件布局；再完成 PTY 与多终端。每批提供可操作预览和回归证据，最终构建安装后在真实应用中检查浏览器/文件/变更/多终端切换、项目初始目录及关闭清理。

不迁移或删除用户文件、浏览器登录状态和历史任务。保留旧应用备份；回退应用不会修改工作区内容。代码在 main 开发，不创建 worktree 或分支。

设计只读审查已完成：跨任务集合归属已按现有会话隔离规则补齐；第 5 节的目录并行规则已由用户确认，不再有实施阻塞。
