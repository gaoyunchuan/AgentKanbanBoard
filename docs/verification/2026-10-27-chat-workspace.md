## 关键自动化回归

- 多会话不增加业务任务节点，项目继承与既有 Thread 目录冻结分开。
- 同树前置依赖校验与祖先等待循环保护；阻塞占位不创建真实 Thread。
- 显式交付要等本轮成功及验收；单轮结束不完成任务。
- 父任务委派、等待子任务、子任务交付、父任务自动恢复经过真实假子进程 JSONL 协议测试。
- 普通聊天到独立只读结果提取经过同样的服务级测试，结果绑定原任务、会话和执行，额外会话不会收到错写结果。
- 人工答复自动恢复、取消后迟到事件不释放业务成功。
- 摘要去重、提取失败重试的来源范围固定；旧来源 Thread 不被摘要 Thread 替换。
- 增量数据库迁移幂等；重启后未知执行不自动重放。

## 用户验收路径

先正常退出旧应用，在仓库根目录执行：

```sh
git pull --ff-only
make run-local
```

建议在首次升级前备份 `~/.codex-kanban`。应用目录副本备份不等于业务数据库备份。

1. 设置页连接本机 Codex，项目页添加或选择已有项目。
2. 新建只有标题的任务，绑定项目，打开即聊天；行尾 `+` 新开同任务会话，任务树节点数不增加。
3. 根任务内添加 A、B；在 B 行 `⋯ → 设置前置任务` 勾选 A，也可点击 `等待：A` 编辑。确认不会混入其他根任务树。
4. 委托 A、B 后验证 B 仍为占位；A 有效交付并完成验收后，B 自动开始且输入包含 A 的结果。
5. 在两个会话分别提取结果，检查同一任务结果区域保留各条来源，不相互覆盖。
6. 运行中增设依赖，确认先停止执行再应用；完成任务时只归档该任务的关联会话，不级联完成子任务。
7. 开启同一会话的侧边浏览器，检查实际网页和 Agent 操作共享同一实例。

## 未完成的真实环境验收与能力边界

本轮未登录用户 Codex 账号、未调用真实模型、未操作用户正式代码库或正式任务数据库。假服务测试、构建与签名完整性不代表真实模型任务成功，也不证明受管理的 Mac 会允许启动。

自动结果采用 Agent 在显式交接工具中提交的结构化总结与证据，并在执行成功及验收后接受；人工提取通过独立只读摘要执行。系统不会把任意最终回答或未读变化当作任务交付。

旧 Desktop 会话保留在设置中的旧看板入口，不隐式接管外部正在运行的会话。应用退出后没有独立守护进程持续运行。文件/终端和多个 Agent 仍遵守工作目录互斥。全自动语义返工影响分析不在本版范围。

详细说明：`docs/chat-workspace.md`；确认设计：`docs/product/interaction-v1.md`。
