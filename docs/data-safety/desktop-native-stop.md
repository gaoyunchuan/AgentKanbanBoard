# 原生命令停止占用约束

资源：SQLite `work_resource_leases`。负责人：桌面调度器。只新增到本次停止修复范围。

| 规则 | 实现约束 |
| --- | --- |
| 基数 | 全局最多 256 行，SQLite trigger 硬拒绝第 257 行；254 行时停止接纳新目录执行，为最多两个在途执行留空间。每行最多 256 个原生线程。 |
| 生命周期 | 正常 Turn 结束删除观察记录，不终止有意后台服务；显式停止或异常终态需查询确认原生终端为空才删除。断线、清理失败、重启转 uncertain，不能按时间自动过期，只有核对后按原 run 解除。 |
| 速率 | 单个 scheduler actor 串行写入，最多两个模型执行。每轮每个新原生线程一次更新，最多 256 次；相同线程不重复更新 JSON。按桌面峰值 1000 个事件/秒作压力预算，容量由硬基数决定，不依赖平均事件速率。 |
| 大小 | SQLite CHECK 按字节限制：run/owner/connection 各 512 B，目录 4096 B，线程 JSON 128 KiB，错误 4096 B。native thread id 256 B。 |
| 容量 | 预留每行 144 KiB（正文及索引/元数据），256 × 144 KiB × 2 安全系数 = 72 MiB。现有任务历史库不在这个新增资源估算范围；SQLite 空闲页可复用，不做自动 VACUUM。 |
| 背压 | 达上限、查询出错、停止结果未知均保留目录互斥；不复制到另一个缓冲区，不自动重放业务。每次核对最多 32 页，每页最多 100 个终端；游标重复/无效结构失败；停止轮询有 8 秒期限及每次 RPC 2 秒上限。 |
| 清理与恢复 | connection+owner+run 标识归属，迟到回调不能清新运行。人工按钮也绑定原 run，活动运行不能解除。清理仅删除占用，不删除报告、执行或业务结果。错误解除会放行目录，因此按钮明确要求先核对进程停止。 |

容量参数都是当前本机实现约束，无需用户补业务流量。未知外部进程不能按 TTL 自动视为消失。该记录属于保守保留的安全状态，允许长期保留但受 256 行硬上限约束。
