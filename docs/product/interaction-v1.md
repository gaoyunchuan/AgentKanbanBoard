# AgentKanban 产品交互设计 · V1

版本：2026-10-27。用途：个人版交互评审稿，不是生产版本，也不是对现有 GitHub 仓库功能的完成声明。

## 交付物与使用

- `AgentKanban-交互原型.html`：单文件可点击原型。保存后用桌面浏览器打开即可；没有 CDN、外部脚本或模型请求。
- `AgentKanban-产品交互设计稿.pdf`：按页面和流程标注的设计稿。
- `screens/`：从同一原型捕获的页面与交互状态。
- `交互验证.json`：本轮 Chromium 模拟交互检查结果。

原型右上角「交互原型 V1 · 说明与演示」可跳转场景、运行自动交接示例或重置。演示数据在浏览器允许时保存在 localStorage；不访问你的真实项目、账户、Codex、Chrome 或任务数据库。

## 1. 产品主线与信息架构

主界面只有一个聊天工作区。左侧窄图标栏提供「会话」「任务」「项目」，另有需要你、设置和原型说明。左侧第二栏随当前视角变化。右侧按需打开任务详情或浏览器面板。任务表单不再占据聊天的默认入口。

### 会话视角

列表按「置顶、活跃、阻塞、完成」组织。置顶与活跃默认展开，阻塞与完成默认收起。点击任务默认打开最近使用的关联会话；没有历史则打开主会话或任务占位。标题旁下拉可切换本任务全部会话。

点击会话时，中央工作区直接显示该会话，不跳到工作台配置表单。顶部任务路径可反向定位全局任务树。悬停或键盘聚焦会话条目时显示所属根任务树，高亮当前任务。

任务或会话完成后，当前正在查看的聊天不自动跳到别处。为了避免列表选中项消失，本稿会展开当前会话所在的完成分组；其他分组保持原状态。

### 任务视角

显示全局任务树，任务与子任务都是独立业务节点。列为任务、关联会话、默认项目、状态和行操作。默认不在行内显示大段 Markdown。

- 单击任务标题：进入该任务的最近会话。
- 单击关联会话标签：准确进入那一个会话。
- 行尾「＋」：为这个任务创建附加会话，不产生子任务。
- 行尾「⋯」：添加子任务、重命名、属性、置顶、删除。
- 悬停任务标题：显示上下文与结果摘要；卡片可移入、可滚动，并能打开详情。
- 搜索：保留命中节点的祖先，避免搜索结果失去层级归属。

新建任务只强制填写标题。创建任务本身不代表已委托执行。直接发送第一条消息即可开展人工会话；在右侧委托给 Codex 后，符合条件则自动执行，不需要人工再发第一条消息。

### 项目视角

展示全部项目及其默认工作目录、未完成任务数和会话数。点击项目进入项目任务范围。任务可显式绑定默认项目，未独立绑定的子任务继承最近上级项目。

聊天输入框上方显示本会话采用的项目和执行环境。创建真实 Thread 时固定工作目录；修改任务默认项目只影响后续新会话，不移动已有会话。

## 2. 对象与关系

“任务即会话”是打开任务后的交互效果，不是把两个对象做成同一条数据。

- Task：标题、父任务、Markdown 上下文、默认项目、委托人、受理 Agent、依赖、业务状态与任务置顶。
- Conversation：归属 Task、会话标题、执行方式、逻辑身份、可选 Codex Thread、固定项目快照、单独置顶与管理状态。
- Run：会话中的一次实际执行，保存运行状态和交接记录。
- Result：归属 Task，来源 Conversation 和执行／消息范围，正文为 Markdown，标注提取方式、时间、阶段与版本关系。

一个任务对应多个会话；一个会话在本期仅归属一个任务。会话不进入任务树成为子节点。一个会话可以多次产生交付结果，不同会话及不同交付轮次的结果均保留。

## 3. 状态设计

### 两个维度，不混用“完成”

会话的管理分组与执行运行态独立。本稿用「本轮结束」表达一次执行已经结束，用「完成」分组表达会话已进入非活跃管理状态。

| 运行态 | 列表／聊天表达 | 主要动作 |
|---|---|---|
| 初始化／逻辑占位 | 没有真实 Thread；显示所关联任务与项目 | 人工附加会话等待首条消息；自动任务满足条件后自动运行 |
| 等待依赖 | 显示等待对象及原因 | 查看前置任务，不显示需要人工点击的“开始”按钮 |
| 进行中 | 运行图标与当前工作；输入框可补充要求 | 停止当前执行，不误完成任务 |
| 待人工确认 | 会话内决策卡和「需要你」提示 | 回答绑定当前请求，随后自动继续 |
| 本轮结束 | 保留输入框继续对话 | 可主动提取结果；不自动完成业务任务 |
| 结果整理中／失败 | 交接卡标明当前进度或失败原因 | 失败只重试整理，不重跑原业务动作 |

暂停、停止确认、连接异常等正式运行细节需要在产品实现时补全；原型不是完整 app-server 协议模拟器。

### 置顶与分组优先级（本稿建议）

置顶是独立属性，不与完成、阻塞构成互斥业务状态。有效置顶 = 任务置顶 OR 会话单独置顶。

分组优先级：完成 > 阻塞 > 置顶 > 活跃。每条会话只出现一次。已完成的置顶会话仍进入完成分组，保留置顶来源，不因置顶回到活跃列表。

任务置顶影响本任务的关联会话，不隐式置顶子任务。取消任务置顶，仍保留会话自己设置的置顶。会话置顶不反向改变任务。

## 4. 占位与自动启动

被依赖阻塞的任务可以在界面上形成派生的任务占位，但不创建真实 Codex Thread。这是展示模型，不是一次实际执行，也不必单独创建一条可运行会话记录。

就绪条件建议为：已委托 Agent、任务未终止、所需依赖交付已成立、项目／环境可用、执行容量允许。就绪后系统自动组装上下文、绑定或创建 Thread、开始执行。

对于已经存在真实 Thread 后又进入等待的情况，保留真实会话和历史，只暂停后续执行，不销毁 Thread。

附加会话默认是人工对话。点「＋」创建逻辑会话，首次发送时创建真实 Thread。自动主会话由调度系统控制，不能因用户展开页面而重复创建。

## 5. 上下文注入

自动会话在启动及从等待恢复时，准备版本明确的输入快照：

1. 当前根任务树的结构、相关状态和任务身份；不是全局所有项目的任务。
2. 当前任务的标题、Markdown 要求和验收约束。
3. 各级父任务的上下文与相关结果。
4. 本次解除依赖的前置任务交付结果。
5. 父任务恢复时，本次等待的子任务交付结果。

历史结果全部保留，但运行只引用与本次工作有关、未被明确替代的内容，来源及版本可追溯。大结果应提供摘要和产物引用，而不是无条件拼接全部原文。

聊天中的「自动执行 · N 项上下文已带入」可展开输入快照。人工对话可从输入框「＋ → 导入任务上下文」预览并加入附件；它不改写任务原文，也不产生子任务。

## 6. 结果提取与交接

### 已确认的规则

自动执行会话在明确交付、需要传递阶段成果的等待等交接点自动提取。普通回复结束、工具调用结束或未读标记变化，不作为自动提取条件。人工开展的附加会话默认保留手动提取；自动会话同样有手动提取入口。

同一个任务的结果区保留全部结果记录。每条结果包含：来源会话、对应执行或消息范围、提取时间、提取方式、阶段、正文与版本关系。

### 人工提取

点击会话右侧「提取结果」后，截取本次来源范围并整理，成功直接追加至任务结果，提供查看和撤销。提取期间重复点击不会重复提交；同一会话同一来源范围已提取时提示已有记录。不同会话和后续交付轮次分别新增记录。

提取期间切换到另一个任务或会话，写入目标仍然是点击时绑定的源任务。人工提取不完成任务，不触发重新执行。

本稿为了避免边执行边读取不完整成果，在运行中或等待确认时暂不开放人工提取；正式产品如需阶段快照，可在明确消息边界后再放开。这属于本稿建议，而非已确认要求。

### 自动交接

执行形成交付 → 提取与保存结果 → 满足验收规则 → 解除相关依赖 → 下一任务自动启动。

前置任务即使被人工标记完成，如果后续依赖的交付仍然缺失，不能凭“完成”标签解除交付等待。需要补结果或由人明确豁免要求。

摘要失败显示“执行已结束，结果整理失败”，保存原业务成果，允许只重试提取。需要这份结果的后续任务等待；无关任务不应被阻塞。

对于父任务，阶段性成果保存后仍须等待子任务、集成和验证。子任务完成不自动证明父目标完成。

### 全部保留与版本有效性

重复提取去重，不同交付轮次追加。手工修订生成新版本，旧结果仍保留并标记已被替代。不同会话出现冲突时，不自动捏造统一正确结论。一期至少保留来源与人工标注能力；不把全自动语义冲突分析作为核心。

## 7. 完成、关闭与删除

任务完成后，本任务的关联会话全部进入非活跃完成分组，不反向要求每个会话最后一次模型调用都必须成功。正在运行的会话先停止并确认，再完成管理状态同步。

只关闭一个会话不自动完成任务。任务完成默认不级联子任务，界面明确提示仍未完成的子任务数。

重新打开任务，本稿恢复其主会话，不自动重启所有历史会话；其他会话保留历史，按需恢复。该默认值需要后续评审。

删除在原型中提供影响范围确认：任务、子任务及相关会话；仍被其他任务依赖时拒绝删除。正式产品建议使用可恢复删除／归档，且在停止有效运行后操作，避免丢失交付来源。本稿删除只作用于演示数据。

## 8. 关键路径与失败反例

场景：实现部署前 Diff，根任务下包含接口契约、前端展示、集成验证。

- 根任务保存共同目标和网络限制。
- 接口任务由 Agent 自动运行；前端与验证分别等待显式依赖。
- 接口完成自动保存结果，前端自动收到接口交付与父任务约束。
- 前端完成后，集成验证启动；所有待交接子任务结果到齐，父任务自动恢复集成。
- 根任务生成自己的最终交付，不能把子任务数量归零当作验收。

最强反例：接口已完成但摘要保存失败。后续不能读取空结果，也不能让用户手动复制接口说明。界面应显示失败交接，只重试整理，成功后恢复原推进路径。

另一反例：用户提取 A 会话结果后切换到 B。请求必须绑定 A 的任务和消息快照，结果不得写入当前页面的 B 任务。

## 9. 视觉与交互规格

- 主参考：用户提供的 Codex 桌面截图及输入框截图。沿用窄导航、浅灰会话侧栏、白色聊天区、底部圆角输入框与项目条。
- 桌面基准：1440 × 960；补查 1024 × 768 和 800 × 720。
- 导航图标栏约 48 px，会话侧栏约 246 px；聊天内容最大宽度约 760 px；属性侧栏约 344 px。
- 较窄桌面窗口属性栏覆盖内容，而不是把聊天挤成极窄列。
- 悬浮卡约 350 px，延迟出现，可移入、滚动，支持 Esc 关闭和点击跳转；不是只能读一行文本的系统 title。
- 任务信息默认隐藏正文；结果面板允许完整阅读和来源跳转。
- 浏览器作为会话旁的独立面板入口。本稿只展示交互承载，不用任意 iframe 冒充完整浏览器控制。

## 10. 本版已确认与建议默认值

已确认：个人、自研、Codex app-server、树形任务、任务多会话、默认项目、右侧额外属性、任务与会话关联展示、上下文／结果 Markdown、自动启动注入上下文、自动提取发生在交接点、全部结果保留来源、前置与子任务结果用于后续恢复。

本稿建议：最近会话优先；附加会话默认人工；创建标题不等于委派；分组优先级与置顶 OR 规则；任务树默认当前根树；已有 Thread 项目固定；当前完成会话分组自动展开；重新打开只恢复主会话；删除保护与恢复机制。

以上建议用于让本轮原型可以跑通，不将其冒充已由用户逐项确认。

## 11. 验证边界

已验证：页面渲染、鼠标和表单交互、任务与会话导航、标题创建、子任务增删改、Markdown 编辑、同树依赖、项目继承与已有会话目录不变、自动交接、手动提取去重与跨会话来源、提取期间切换、单向置顶、任务完成归档、父任务等待恢复、窄窗无整页横向溢出。

验证环境：Chromium，对生成 HTML 通过页面内容加载进行模拟交互验证，不代表在用户 Mac 上安装通过。浏览器本地文件启动、localStorage 持久化、屏幕阅读器与全键盘焦点循环尚未单独验收。

未验证／未接入：真实 Codex、真实账号与模型、生产调度、权限提升、实际 Chrome 控制、Git 文件修改、实际交付内容的真实性判断。原型中的摘要采用示例内容，不是模型总结服务；流程中的验收通过是演示状态，不是模型说成功即可上线。

本轮没有修改 AgentKanbanBoard 仓库。
