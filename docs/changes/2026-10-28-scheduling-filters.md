# 2026-10-28 · 任务筛选、开始时间与 Codex 配置诊断

## 本轮需求

- 任务状态用不同图形区分：待办虚线圈、进行中播放圈、完成勾选、取消叉号，依赖阻塞使用锁。任务树、任务侧栏、状态菜单和筛选器共用同一组件。
- 全局任务树支持状态多选、项目多选、更新时间筛选（24 小时、周视图滚动 168 小时、30 天）、关键词、展开/折叠全部、重置。
- 关键词是整树定位：标题或 Markdown 上下文命中任意任务，就选中该任务所属的完整根任务树，包含所有兄弟分支与后代。仅关键词搜索时展示整棵树，不混入无关键词命中的其他根树。
- 状态、项目、更新时间是树内节点筛选：同维度多选取并集，不同维度在同一节点上取交集。关键词命中的节点本身可以不符合这些条件，仍能定位同树中符合条件的其他任务。为通过筛选的节点补必要祖先，标注“层级路径”且不计入符合筛选数；其余不符合条件的分支不展示。无关键词时保持普通节点筛选；整树没有符合条件的节点时不展示空树。
- 筛选条件、折叠节点、分页和滚动位置存入带版本的本机缓存。离开再返回保留条件；结果根据最新任务数据重新计算，不锁住过期结果。左侧搜索继续独立。
- 周视图使用已有 `activity_at` 语义（API 名字仍为 `updated_at`）。读取、轮询、展开与排序不刷新；实际任务内容、项目、依赖、时间或结果变化会刷新相关任务。相同值提交不刷新。

## 开始时间

右侧“属性与设置”增加可选“开始时间”，注明设备时区；持久保存为规范 UTC 时间，不使用旧版 date-only `start_date`。

- 自动执行条件：已经委托 Agent、任务未终止/暂停、时间已到（或未设置）、依赖交付成立、目录/环境/权限及容量检查通过。
- 时间是最早允许自动执行时间，非强制 deadline；保存时间不等于委托，清空恢复现有规则。
- 未到时间显示等待开始时间，主会话可以保留逻辑身份，但不得创建真实 Thread/Turn，也不消耗模型轮询。
- 调度就绪检查与事务领取执行都检查时间；到点后最多领取一次。普通用户启动的人工附加会话不受自动启动时间限制。
- 当前执行或停止确认未结束时，拒绝改时间。暂停、人工等待、环境异常、取消和完成不因时间变更而自动恢复。
- 子任务有独立的可选时间，不隐式继承父任务时间；父子工作关系仍由任务委派/依赖表达。
- 本期没有系统级守护进程。应用退出或 Mac 休眠时不执行；重新运行后以持久状态重新检查，不重放中断后结果不确定的执行。

## Codex 配置错误与兼容版本选择

用户报错是 `failed to load configuration ... invalid type: integer 10, expected struct AgentRoleToml`，不能据此判定 dynamicTools 不受支持。

- 初始化后用只读 `config/read` 预检同一个 HOME/CODEX_HOME 配置，失败时关闭候选子进程；不会创建测试 Thread 或 Turn。
- 自动模式在 Desktop、PATH、常见 CLI 和 NVM 候选中选择通过连接/配置预检的程序；显示实际程序路径和 server userAgent。显式路径覆盖不被静默替换。
- 失败候选的迟到断连事件不能覆盖已经成功的新连接或最终诊断。
- 只在 RPC 明确报告 dynamicTools 不支持时提示该能力；配置错误保留文件、行号、具体类型错误，解释 AgentRoleToml 与 scalar/table 的冲突。
- 不复制 token，不改写配置，不删除未知字段，不绕过配置/审批规则，也不把数字 `10` 猜改为字符串。
- 若所有候选都不能加载同一配置，仍会阻塞并明确报错，需要核对报错位置实际键名及其所属 TOML 节。截图不包含键名，无法在远端确定应修改哪一项。
- 项目级配置与全局预检不同；只有在真实工作区启动时发现的配置错误仍会明确显示，不能将连接预检当成完整工作区兼容证明。

## 验收场景

1. 输入某个子任务独有的关键词：其根任务、兄弟分支和所有后代均展示。再多选待办与进行中、周视图及项目：仅显示所定位树中同时符合这些条件的节点及必要祖先；即使命中关键词的是已完成的旧任务，也能展示同树其他待办任务。切换页面后条件和折叠状态保留，结果随最新数据计算。
2. 全部折叠/展开；切到会话或设置后返回，确认条件、分页与折叠保留；重置恢复全部任务。
3. 未委托任务设置未来时间：不执行；委托后仍保持占位；改为已到时间后自动启动，不需要人工发送“继续”。
4. 到点但依赖未完成、手动暂停、权限等待或目录不可用：不越过该条件。
5. 首个 Codex 候选在配置预检失败、下一个通过：选择通过的程序。全部失败时保留配置错误，不附加无依据的 dynamicTools 结论。
