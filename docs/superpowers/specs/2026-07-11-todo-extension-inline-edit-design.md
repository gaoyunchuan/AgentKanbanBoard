# To Do 扩展信息单条编辑设计

## 目标

“过程跟踪”和“结果复盘”中的每条记录支持双击原位编辑，同时保持 Markdown 命名链接的短名称展示和单击跳转能力。

## 数据边界

- 继续使用换行分隔的 Markdown 兼容字符串存储扩展信息，不修改数据库结构。
- 每个非空行视为一条独立记录。
- 符合 `[名称](http://...)` 或 `[名称](https://...)` 的完整行视为命名链接，其余内容视为普通文本。
- 保存时只替换当前行，其他记录的内容与顺序不变。

## 交互

- 双击普通文本后，当前行切换为单行输入框并自动聚焦。
- 双击命名链接后，当前行切换为“显示名称”和“URL”两个输入框。
- `Enter` 保存，`Esc` 取消并恢复原内容。
- 保存空文本、空名称或非法 URL 时不修改原记录；URL 仅接受 `http://` 和 `https://`。
- 单击命名链接继续打开目标地址。单击操作延迟约 200ms 执行；若期间检测到双击，则取消跳转并进入编辑，避免误打开网页。
- “过程跟踪”和“结果复盘”复用同一套编辑能力。

## 实现范围

- 将扩展字段按行解析为可展示、可编辑的记录。
- 编辑状态保留在对应扩展区域组件内部，不改变任务领域模型。
- 通过现有 `onChange` 更新完整扩展字段字符串，并沿用当前任务快照持久化链路。

## 验收与测试

- 双击普通文本可修改当前行，其他行不变。
- 双击命名链接可分别修改名称与 URL，保存后仍以命名链接展示。
- `Esc` 取消编辑，非法或空内容不会覆盖原值。
- 单击链接只打开一次；双击链接不打开网页并进入编辑。
- 两个扩展区域行为一致，现有新增文本、新增链接和协议白名单测试继续通过。
