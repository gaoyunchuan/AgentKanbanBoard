# Thread 与 Todo Task 双向关联设计

## 背景

Codex Thread Kanban 用 Thread 管理 Codex 会话，用 To Do List 管理树形任务。当前两类对象相互独立，用户无法从 Thread 看出它服务于哪个任务，也无法从 Task 汇总相关 Thread。

本功能为两者增加本地双向关联。关联属于低频辅助信息，不应改变现有列表的扫描效率，也不应占用窄窗口中的常驻注意力。

## 目标

- 在任意状态的 Thread 中关联一个未完成 Task，选择范围覆盖任意层级的子任务。
- 在任意状态的 Task 中关联多个待审核或挂起 Thread。
- 保证双向展示一致：任何一端的关联、迁移或解除都在同一前端渲染周期反映到另一端。
- 保持现有折叠列表的信息密度，只在对象展开后展示和管理关联。
- 在日常使用的窄而高窗口中完成查看、搜索、选择、迁移和解除操作。

## 非目标

- 不根据关联自动修改 Task 或 Thread 状态。
- 不把关联信息加入 Thread 折叠行、Task 折叠行、筛选栏或常驻导航。
- 不支持一个 Thread 同时关联多个 Task。
- 不改变 Codex Desktop 的 Thread 数据，也不让关联进入 Codex Thread 同步主链路。
- 不提供批量关联、批量迁移或自动推荐关联对象。

## 关系与约束

关联关系为一对多：

- 一个 Thread 最多关联一个 Task。
- 一个 Task 可以关联零个或多个 Thread。
- 关联目标可以是根 Task，也可以是任意层级的子 Task。
- Task 或 Thread 自身状态不限制用户从该对象发起关联；状态只限制选择器中的候选对象。

候选规则如下：

| 发起端 | 候选对象 | 可选择状态 |
| --- | --- | --- |
| Thread | Task | `todo`、`in_progress` |
| Task | Thread | `review_pending`、`suspended` |

`completed` 和 `cancelled` Task 不属于“未完成 Task”，不进入 Thread 端候选列表。其他状态的 Thread 不进入 Task 端候选列表。

候选限制只作用于新建或更换关联。关联建立后，即使 Task 完成、取消，或 Thread 状态离开待审核和挂起，既有关联仍然保留。

## 设计原则

### 低打扰

Thread 和 Task 折叠时不显示关联图标、关联数量或“未关联”提示。用户只有展开对象后才看到关联区域。

### 就地完成

查看、选择、更换和解除均在当前展开区内完成，不打开模态框，不跳到单独管理页。

### 保留上下文

Task 候选展示父级路径，Thread 候选展示项目、状态和现有关联归属，避免窄窗口中标题截断后无法判断对象。

### 及时反馈

选择后在同一交互周期更新界面并保存。成功操作使用轻量提示条；失败时恢复原状态并提供重试。迁移和解除提供 5 秒撤销，不增加确认弹窗。

## Thread 端交互

### 展开态

在 Thread 现有展开详情的末尾增加“关联 Task”区域。折叠 Thread 时该区域完全不可见。

- 未关联时显示单行选择框，占满展开区可用宽度，文案为“选择未完成 Task…”。
- 已关联时在同一位置显示 Task 名称、解除按钮和展开选择器按钮。
- Task 名称可点击，点击后切换到 To Do List；若当前搜索或状态筛选隐藏目标，则把状态筛选切换为“全部”、清空搜索。随后展开目标的全部祖先，按当前 Todo 树顺序计算目标所在页，展开目标详情，把目标行滚动到可视区域中部并将焦点移到目标行。目标已不存在时保留当前页面并提示“关联的 Task 已不存在”。
- 长名称保持单行并截断；悬停或键盘聚焦时显示完整名称。

### Task 选择器

点击选择框后，在字段下方就地打开下拉选择器并自动聚焦搜索框。

- 无搜索词时按当前 Todo 树顺序展示候选，使用缩进表达父子层级。
- 若可选子 Task 的祖先已完成或取消，祖先只作为不可选择的层级上下文展示，子 Task 仍可选择。
- 搜索范围包含 Task 标题，使用去除首尾空格后的不区分大小写子串匹配，不做模糊匹配；搜索结果扁平展示，并在第二行显示完整父级路径。
- 根 Task 只显示标题；子 Task 显示“父 Task / … / 子任务”的路径信息。
- 当前已关联 Task 固定显示在选择器顶部。即使它后来完成或取消，也显示为“当前关联、不可重新选择”，不混入可选候选。
- 选择其他 Task 时直接替换原关联，不弹确认框。
- 没有结果时显示“没有符合条件的 Task，可尝试其他关键词”。

## Task 端交互

### 展开态

在 Task 现有“过程跟踪”和“结果复盘”之后增加“关联 Threads”区域。折叠 Task 时该区域完全不可见。

- 标题右侧显示当前关联数量。
- 每个已关联 Thread 占一行，展示 Thread 标题和状态。
- Thread 名称沿用现有打开 Codex 的能力，不改变当前 Task 的展开状态。
- 每行提供解除按钮。
- 列表下方显示低强调的“关联 Thread”按钮，并注明“仅待审核、挂起”。
- 没有关联时不显示额外说明，只保留“关联 Thread”按钮。

### Thread 选择器

点击“关联 Thread”后，在按钮下方就地打开选择器并自动聚焦搜索框。

- 搜索范围包含 Thread 标题和项目名称，使用去除首尾空格后的不区分大小写子串匹配，不做模糊匹配。
- 候选按“待审核”“挂起”分组，待审核在前。
- 组内沿用当前 Thread 列表的排序，不引入新的排序规则。
- 每个候选展示标题、项目、状态和现有关联归属。
- 已关联当前 Task 的 Thread 不重复出现在候选列表。
- 已关联其他 Task 的 Thread 仍可选择，并显示“当前关联：Task 名称”。
- 选择一个 Thread 后关闭选择器并立即保存；需要继续关联时再次打开选择器。
- 没有结果时显示“没有符合条件的 Thread，可尝试其他关键词”。

### Thread 迁移

选择已关联其他 Task 的 Thread 时，直接把关联迁移到当前 Task：

1. 从旧 Task 的关联列表移除该 Thread。
2. 把 Thread 加入当前 Task 的关联列表。
3. 更新 Thread 展开区中显示的关联 Task。
4. 关闭选择器并显示“Thread 已移至‘Task 名称’”提示条。
5. 提示条提供 5 秒“撤销”操作；撤销后恢复原关联。

迁移是一次原子操作，任何一步保存失败都恢复迁移前状态。

## 解除关联

Thread 端和 Task 端均可通过关联项旁的解除按钮解除关系。

- 操作不弹确认框。
- 界面立即移除关系并开始保存。
- 成功后显示“已解除关联”提示条，并提供 5 秒“撤销”。
- 保存失败时恢复原关联，显示“关联保存失败，已恢复原状态”，并提供“重试”；重试会基于最新持久化状态重新执行刚才失败的操作意图。
- 撤销必须恢复解除前或迁移前的唯一关联，不能产生一个 Thread 同时关联多个 Task 的中间状态。
- 同一 Thread 发生新的关联、迁移、解除或删除操作时，旧提示条的撤销立即失效；撤销目标已删除时提示“无法撤销，目标已不存在”。
- 撤销恢复的是曾经存在的历史关系，不重新应用当前候选状态过滤；只要 Thread 和原 Task 仍存在，即使状态已变化也允许恢复。

## 窄窗口适配

- 关联区始终使用展开区的可用宽度，不新增右侧固定列。
- 下拉选择器与触发字段同宽，最大高度为 280px；内容超出后在选择器内部滚动。
- 标题单行截断，辅助信息另起一行，不横向撑开窗口。
- Task 树每层缩进 12px，视觉缩进最多 36px；更深层级继续通过完整父级路径表达。
- Task 端的关联 Thread 每行只保留标题、状态、打开和解除操作。
- 打开选择器不改变列表整体宽度，也不遮挡当前对象的标题。
- 以 650px 内容宽度、100% 系统缩放作为窄窗口验收基线。

## 键盘与可访问性

- 关联字段和按钮均可通过 Tab 聚焦，并具有明确的可访问名称。
- 选择器使用 `combobox` + `listbox` 语义，候选使用 `option`，并向辅助技术播报候选数量和当前选中项。
- `Enter` 或 `Space` 打开选择器；`Esc` 关闭并把焦点还给触发控件。
- 搜索框中使用方向键移动候选，`Enter` 选择，当前候选具有可见焦点样式。
- Task 层级不能只靠缩进表达，辅助路径需要被屏幕阅读器读取。
- 状态不能只靠颜色区分，必须同时显示中文状态文本。
- 解除、撤销和重试均使用文字或带工具提示的标准图标按钮。
- 图标操作的可点击区域不得小于 28px × 28px；保存失败和撤销结果通过礼貌级 live region 播报。

## 数据模型与更新边界

- 使用单一关联记录表达关系，逻辑键为 `thread_id`，值为 `task_id`；`thread_id` 必须具有唯一约束。
- `thread_id` 和 `task_id` 必须使用外键或等价数据库约束保证目标存在，并在目标记录删除时级联清理关系。
- 新建、更换、迁移和解除都通过一次后端事务完成，不能由前端组合多次写请求模拟原子迁移。
- 关联写入、对象状态写入和对象删除由数据库事务线性化：关联事务在写入时校验对象存在和候选状态。若状态变更或删除先提交，关联失败；若关联先提交，后续状态变更保留关系，后续删除级联清理关系。
- 前端维护一份按 `thread_id` 索引的关联状态。Thread 展开区和 Task 展开区都从这份状态派生展示，成功操作后在同一渲染周期更新两端。
- 对象展开时按需加载关系；加载结果合并进共享关联状态。已展开的另一端不需要等待下一次轮询才能看到变化。
- 每个 Thread 的写操作进入独立串行队列。新操作必须等待同一 Thread 的前一个写操作完成，不采用“任意最后返回覆盖当前状态”的策略。
- 每次操作携带本地操作序号。响应只可确认对应操作；旧响应不得回滚或覆盖之后已排队的操作。
- 若早期操作失败且同一 Thread 已有后续操作排队，取消该 Thread 的全部后续排队操作，重新加载该 Thread 的持久化关联并以它覆盖本地状态。失败提示提供对原失败操作的“重试”，被取消的后续操作不自动重放，并提示“后续操作已取消，请重新操作”。

## 数据一致性与生命周期

- 关系以 Thread 为唯一约束主体：同一个 `thread_id` 最多存在一条有效关联。
- 从任一端操作后，两端读取同一份关系数据，不分别保存两份可分叉的状态。
- 关联变更不触发 Codex Thread 同步，也不进入 Thread 列表的五秒轮询重链路。
- 周期刷新 Thread 数据时，前端按 `thread_id` 保留并合并已加载的关联信息，避免界面闪回。
- 删除 Task 与清理它的全部 Thread 关系必须处于同一数据库事务；清理失败时 Task 删除也失败，不产生孤儿关系。
- Thread 记录被明确从本地数据库删除时，在同一事务中清理对应关系；同步暂时未返回某个 Thread 不等同于永久删除，不触发清理。
- Task 或 Thread 仅改变状态、归档或恢复时不自动解除关系。
- 当前 Todo 的删除为永久删除；若未来增加回收站或恢复能力，需要另行设计关联恢复规则，本功能不预留隐式恢复行为。

## 加载与错误状态

- 展开对象后再加载其关联详情，折叠列表不为关联功能增加常驻请求。
- 加载中用一行与关联控件等高的占位替换关联控件；数据返回后可以按真实关联数量自然增高，但加载过程不产生额外的空白面板或模态层。
- 加载失败时在关联区显示“关联加载失败”和“重试”，不影响 Thread 或 Task 的其他详情。
- 保存采用乐观更新。若失败时同一 Thread 没有后续排队操作，则回滚到操作前快照；若已有后续排队操作，则按“取消后续队列并重新加载持久化状态”的规则处理。
- 乐观更新在用户完成选择的同一交互周期内发生；保存超过 300ms 时在关联区显示行内“保存中”，但不阻止用户浏览其他对象。
- 快速连续操作遵循“同一 Thread 串行、不同 Thread 可并行”，旧请求返回不能覆盖新状态。
- 选择器打开后若候选状态发生变化，后端按写入时的最新状态再次校验。候选已不符合条件时拒绝写入、刷新候选并提示“对象状态已变化，请重新选择”。

## 验收标准

### Thread 端

- 任意状态的 Thread 展开后均可选择一个 `todo` 或 `in_progress` Task。
- 选择器可以选中根 Task 和任意层级子 Task，并能通过父级路径区分同名子 Task。
- `completed`、`cancelled` Task 不出现在候选中。
- 更换 Task 后旧关联被替换，Thread 不会同时关联两个 Task。

### Task 端

- 任意状态的 Task 展开后均可关联多个 `review_pending` 或 `suspended` Thread。
- 其他状态的 Thread 不出现在候选中。
- 已关联其他 Task 的 Thread 仍可选择，选择后原子迁移到当前 Task。
- 同一个 Thread 不会在同一 Task 的关联列表中重复出现。

### 双向一致性

- 从 Thread 端关联、替换或解除后，Task 端展示同步更新。
- 从 Task 端关联、迁移或解除后，Thread 端展示同步更新。
- Task 或 Thread 状态变化后既有关联保留。
- 删除对象、保存失败、重试和撤销均不会破坏唯一关联约束。

### 视觉与操作

- 折叠列表与功能上线前保持相同的行高和常驻信息。
- 在 650px 内容宽度、100% 系统缩放下，不出现横向滚动；搜索、选择、更换、迁移、解除、撤销和重试入口均可见且可操作。
- 鼠标和键盘均可完成搜索、选择、更换、迁移、解除、撤销和重试。

## 测试重点

- 候选状态过滤与 Task 子树路径展示。
- Thread 唯一关联约束和 Task 多 Thread 关系。
- 已有关联 Thread 的跨 Task 原子迁移与撤销。
- 两端解除、保存失败回滚和乱序请求保护。
- Task 完成、取消及 Thread 状态变化后关联保留。
- Task 删除和 Thread 记录明确从本地数据库删除后的关系清理。
- 窄窗口布局、标题截断、选择器滚动与键盘导航。
