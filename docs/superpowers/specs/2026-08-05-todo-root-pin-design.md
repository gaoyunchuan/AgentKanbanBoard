# To Do Root 任务置顶设计

## 背景与目标

To Do List 当前按顶层任务树的完成度派生展示顺序，同一完成度分组内保持持久化的 `position`。本次增加人工置顶能力，让需要持续关注的顶层任务树稳定显示在列表最前方，同时不改变子任务的独立状态和层级语义。

目标如下：

- 仅 root 任务可以由用户置顶或取消置顶。
- 支持多个 root 任务同时置顶。
- 置顶优先级高于现有完成度分组，包括已完成和已取消的置顶任务。
- 置顶任务从 root 变为非 root 时，置顶状态自动转移到它当前所属的新 root。
- 置顶 root 的主任务行使用浅绿色背景。
- 不新增表格列；置顶标识位于现有“任务”单元格内，仅占一个图标位。

## 方案选择

采用在 `todo_tasks` 中增加显式 `pinned` 布尔字段的方案。前端和后端任务模型同步携带该字段，旧数据库通过增量迁移增加默认值为 `false` 的列。

没有采用独立置顶关系表，因为置顶是任务自身的稳定展示属性，额外关系表会增加快照删除、悬空关系和事务一致性处理。也不使用负数 `position` 编码置顶，因为这会混合置顶状态与同级顺序，并与现有位置归一化和完成度排序产生冲突。

## 数据模型与持久化

- TypeScript 的 `TodoTask` 和 `BackendTodoTask` 增加 `pinned`。
- Rust 的 `TodoTaskInput` 和 `TodoTaskRecord` 增加 `pinned`。
- `todo_tasks` 增加 `pinned INTEGER NOT NULL DEFAULT 0`。
- 新建任务默认不置顶。
- 加载旧数据时，缺失的置顶值按 `false` 处理。
- 快照保存继续沿用现有 upsert；更新任务时写入 `pinned`，并继续保留 `created_at`。

后端保存快照时也执行置顶归一化，确保异常或旧版调用方不能写入“非 root 任务自身处于置顶状态”的数据。归一化根据 `parent_id` 沿父链寻找当前 root；遇到缺失父节点或环时停止追踪，并以可确定的当前节点为边界，避免保存过程无限循环。

## 树操作与置顶转移

前端提供一个纯函数统一归一化置顶状态，并在所有任务变更进入 React state 和持久化之前调用。规则如下：

1. 未置顶任务不触发转移。
2. 已置顶且仍为 root 的任务保持置顶。
3. 已置顶任务变成非 root 时，沿父链找到它当前所属的 root。
4. 清除原任务的 `pinned`，并将找到的新 root 设置为 `pinned`。
5. 如果新 root 已经置顶，结果保持不变。
6. 多个置顶子树汇入同一新 root 时，最终只保留该 root 的一个置顶状态。

该规则适用于 Tab 缩进、拖放导致的层级变化以及其他通过统一任务更新入口产生的层级变化。取消置顶只修改当前 root，不影响其子任务。

## 展示顺序

列表按完整顶层任务树为单位排序，不拆散父子树：

1. 所有置顶 root 任务树排在最前方。
2. 置顶组内保持 root 的持久化 `position` 顺序，不再按完成度重排。
3. 未置顶 root 任务树继续使用现有规则：没有完成态节点、完成与未完成混合、全部完成依次展示；同组内保持 `position`。
4. 子任务不单独参与置顶或完成度分组。

置顶和取消置顶不改写 `position`。因此取消置顶后，任务树会按原位置和完成度重新进入普通分组。

## 交互与视觉

- root 任务的现有状态菜单增加“置顶”或“取消置顶”操作。
- 子任务菜单不展示置顶相关操作，也不预留空白位置。
- 置顶 root 在现有“任务”单元格内显示图钉图标，不新增表头或网格轨道；图标只占一个图标位。
- 图钉是状态标识，不单独承担切换操作，避免与标题编辑、拖拽和展开按钮形成密集点击区；置顶切换统一从菜单完成。
- 置顶 root 的整条主任务行使用浅绿色背景；展开态、悬停态仍保持绿色语义，只调整深浅反馈。
- 子任务行和展开详情面板不继承绿色背景。
- 图标提供可访问名称或标题，颜色不是识别置顶状态的唯一手段。

## 错误处理与兼容性

- 数据库迁移对已有数据库安全追加默认列，不重建或删除现有任务数据。
- 前端映射允许后端历史测试夹具暂时缺少 `pinned`，统一解释为 `false`。
- 后端归一化作为持久化边界兜底；前端归一化保证用户操作后立即得到正确视觉反馈。
- 保存失败继续使用现有消息提示和保存队列，不改变本次内存中的交互反馈模型。

## 验收与测试

自动化测试覆盖：

- 旧数据库迁移后所有既有任务默认为未置顶。
- `pinned` 能随任务快照保存、加载，并保留既有 `created_at` 语义。
- 多个置顶 root 排在所有未置顶任务树之前，且置顶组保持 `position`。
- 未置顶任务继续遵守现有完成度排序。
- 置顶 root 通过 Tab 或跨层级移动变成子任务后，原任务取消置顶，新 root 自动置顶。
- root 菜单提供置顶/取消置顶，子任务菜单不提供该操作。
- 置顶 root 显示图钉且主任务行具有浅绿色背景，子任务与展开详情不染色。
- 置顶和取消置顶均进入现有快照持久化流程。
