# To Do List 默认每页 200 条设计

## 背景

To Do List 当前使用固定分页大小 `50`。任务数量增加后，用户需要更频繁地翻页，不符合该列表以集中浏览和编辑为主的使用方式。

## 目标

- 默认每页展示 `200` 条可见任务。
- 超过 `200` 条时继续使用现有“上一页/下一页”分页。
- 搜索或状态筛选变化后继续重置到第一页。
- 从 Thread 关联定位 Task 时，继续根据排序后的任务位置自动进入正确页。
- 不改变任务排序、树结构、筛选、持久化和关联逻辑。

## 方案

保留现有分页架构，只把 `TodoListView` 中的固定页大小常量从 `50` 调整为 `200`。现有 `pageCount`、切片范围、页码收敛和 `todoTargetPage` 调用都继续复用该常量，因此不新增配置、状态或数据迁移。

同步修改分页回归测试：使用 `201` 条任务验证第一页 `200` 条、第二页 `1` 条，并验证搜索后回到单页结果。关联定位的页码纯函数已有独立覆盖，本次增加视图层第 `201` 条任务定位到第二页的回归，确保调用方使用新的页大小。

## 非目标

- 不提供 50、100、200 等页大小切换控件。
- 不把页大小保存到本地配置或数据库。
- 不移除分页，也不改为虚拟列表或无限滚动。
- 不修改后端接口或数据库。

## 验收标准

- `200` 条任务时页码为 `1 / 1`，页面展示 `200` 条。
- `201` 条任务时页码为 `1 / 2`，第一页展示 `200` 条；点击下一页后展示第 `201` 条且只有 `1` 条。
- 搜索和状态筛选继续把页码重置为第一页。
- 关联定位第 `201` 条 Task 时自动进入第二页并聚焦目标。
- 完整前端测试、生产构建和 `git diff --check` 通过。

## 风险

单页 React 节点数最多从 `50` 增加到 `200`，会提高初次渲染成本；当前列表规模和明确需求接受这一取舍。此次不引入虚拟化，后续只有在确定性性能数据表明存在问题时再单独评估。
