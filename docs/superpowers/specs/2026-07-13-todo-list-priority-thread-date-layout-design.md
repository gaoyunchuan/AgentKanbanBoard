# To Do List 排序、Thread 列与日期布局设计

## 背景

现有 To Do List 以人工 `position` 展示树形任务，关联 Thread 仅在任务展开后可见，列表同时展示起始日期、预期结束日期和实际结束日期。随着任务数量增加，已完成任务占据列表前部，关联信息在折叠态不可见，三个日期列也挤压了任务标题空间。

本次改造在保留树结构、手动组内顺序和现有关联管理能力的前提下，按任务树完成度自动调整展示优先级，并压缩列表列宽。

## 目标

- 顶层任务树按“全部未完成、部分未完成、全部已完成”依次展示。
- 折叠行第二列直接展示该任务关联的全部 Thread。
- 新建任务自动记录添加日期，并默认把预期结束日期设为本地日历的下一天。
- 起始日期不再展示或编辑，但保留历史数据兼容性。
- 预期结束日期和实际结束日期保持完整日期格式，同时缩小列宽。
- 保持搜索、筛选、分页、树编辑、状态、拖拽和 Thread 关联能力可用。

## 非目标

- 不删除 `todo_tasks.start_date` 字段，也不清理已有起始日期数据。
- 不为已有且预期结束日期为空的任务回填默认值。
- 不修改 Thread 与 Task 的一对多关系和候选状态规则。
- 不把关联数据加入 `BoardData` 或五秒自动刷新链路。
- 不新增数据库完成度分组字段，不因状态变化批量重写任务位置。

## 完成度分组与排序

### 分组单位

只对顶层任务树分组。每个根任务及其全部后代作为一个不可拆分的展示单元；子任务在树内继续按现有 `position` 展示，不单独按完成度重新排序。

### 状态归类

`completed` 和 `cancelled` 均视为完成态，`todo` 和 `in_progress` 均视为未完成态。

- 全部未完成：树内没有任何完成态节点。
- 部分未完成：树内同时存在完成态和未完成态节点。
- 全部已完成：树内所有节点均为完成态。

展示优先级固定为：

1. 全部未完成
2. 部分未完成
3. 全部已完成

同一分组内按根任务现有 `position` 保持人工顺序。排序是前端派生结果，不修改持久化位置。任务状态变化后，其顶层任务树在下一次渲染中自动移动到对应分组。

### 搜索、筛选与分页

完成度基于完整任务快照计算，不受搜索和状态筛选影响。先对完整顶层任务树排序，再沿用现有筛选规则保留匹配任务及祖先，最后分页，避免同一任务在不同筛选条件下得到不同完成度。

### 拖拽

同一完成度分组内的顶层任务继续允许手动调整相对顺序。跨完成度分组拖拽不执行位置变更，避免界面在保存后又被自动分组拉回。子任务继续遵守现有同级拖拽规则，并保留树结构。

## 列表布局

列表列顺序调整为：

`任务 | 关联 Thread | 预期结束日期 | 实际结束日期 | 操作`

- 任务列使用剩余宽度，空间不足时截断标题。
- 关联 Thread 列约 `180px`，展示全部关联 Thread 的紧凑标签。
- 预期结束日期和实际结束日期各约 `96px`，继续显示完整 `YYYY-MM-DD`。
- 操作列压缩到满足现有子任务和更多操作入口的最小宽度。
- 约 650px 内容宽度下不出现横向溢出；任务标题优先收缩，Thread 标签允许换行并自然增加当前行高度。

起始日期表头、单元格和编辑入口全部移除。

## 关联 Thread 第二列

进入 To Do List 时，通过现有关联 command 单独加载一次关联数据，使折叠行能够展示关联标签。该加载不进入 `BoardData`，也不加入周期刷新。

每个标签只展示 Thread 标题：

- 标签过长时在自身宽度内截断。
- 多个标签按现有 Thread 列表顺序全部展示，并在列内换行。
- 点击标签直接切换并定位到对应 Thread。
- 没有关联时显示 `—`。
- 加载失败时显示紧凑的“加载失败”和“重试”入口，不影响任务其他字段。

展开详情中保留现有完整关联区域，继续支持新增关联、迁移、解除和失败恢复。

## 添加日期与默认预期结束日期

### 添加日期

数据库已有 `todo_tasks.created_at`，无需迁移。前端任务模型补充该字段，并在展开详情顶部增加只读元信息：

`添加日期：YYYY-MM-DD`

后端时间戳按用户本地时区转换为日期，不显示时分秒，不提供编辑入口。新任务在保存完成前先显示本地创建日期；重新加载后以数据库 `created_at` 为准。

### 默认预期结束日期

改造后所有新任务均把预期结束日期初始化为本地日历的下一天，包括：

- 新建根任务；
- 新建子任务；
- 在当前任务前插入同级任务；
- 在当前任务后插入同级任务。

下一天按日历日计算，包括周末，并正确处理跨月和跨年。已有任务不回填，用户仍可通过双击日期单元格修改或清空默认值。

## 数据流与兼容性

- `created_at` 从后端 `TodoTaskRecord` 映射到前端 `TodoTask`，保存输入仍由后端维护创建时间。
- `start_date` 继续参与前后端兼容映射和快照保存，避免一次普通编辑清空历史值，但 UI 不展示它。
- 完成度分组由纯函数从当前任务快照计算，不新增 schema 或后端查询。
- Thread 标签使用现有共享 `linksByThread` 和 Thread 快照派生，成功关联、迁移或解除后与展开详情在同一渲染周期更新。
- 新的关联首屏加载只在进入 To Do List 时发生，不改变 Codex Thread 同步、评论懒加载或轮询边界。

## 异常处理

- 任务保存失败继续沿用现有底部消息提示，不伪造持久化成功。
- 关联加载失败仅降级 Thread 列和展开关联区，并提供重试；任务编辑保持可用。
- 找不到已关联 Thread 时不渲染无效可点击标签，展开区沿用现有关联一致性处理。
- 跨组拖拽不保存无效顺序，界面保持当前自动分组结果。

## 验收标准

### 排序

- 根任务树按三档完成度稳定排序，取消状态按完成态计算。
- 状态变化能使整棵树移动分组，父子节点不被拆散。
- 同组手动顺序保留，子任务顺序不因完成度改变。
- 搜索、状态筛选和分页不会改变完成度计算口径。

### 日期

- 四种新建入口的预期结束日期均默认为本地明天，并覆盖跨月、跨年。
- 已有空日期不回填。
- 展开详情显示只读添加日期，起始日期在列表和详情中均不可见。
- 预期和实际结束日期保持完整日期展示及双击编辑。

### Thread 列

- 第二列展示全部关联 Thread 标签，标签可点击定位到 Thread。
- 多标签换行时不遮挡日期和操作列。
- 无关联、加载中、加载失败和重试状态可辨识。
- 展开详情中的关联、迁移、解除和撤销能力不回归。

### 回归与视觉

- 关联关系唯一约束、迁移、失败回滚和撤销测试通过。
- 在 1440×1024、1024×768 和约 650px 内容宽度下检查布局；页面无横向溢出。
- 普通浏览器预览不调用 Tauri bridge，控制台错误为零。
