# To Do 任务拖放排序设计

## 目标

恢复清晰、稳定的同级任务拖放排序，避免拖放时误改任务层级。

## 交互规则

- 拖拽手柄始终可见，不依赖行悬停才能发现。
- 目标任务行上半区：插入到目标任务之前，显示顶部蓝色横线。
- 目标任务行下半区：插入到目标任务之后，显示底部蓝色横线。
- 拖放只调整同级顺序，沿用目标任务的 `parentId`；拖动任务连同其全部后代一起移动。
- 创建子任务继续使用 `Tab` 或“子任务”按钮，拖放不再改变层级。
- 禁止把任务移动到自身或自身后代中，非法落点不改变数据。
- 拖动结束或离开有效目标后清除视觉提示。
- 排序结果继续通过完整任务快照持久化，刷新后顺序保持不变。
- Tauri 窗口关闭内部文件拖放处理器，确保 macOS WKWebView 把 HTML5 DOM 拖放事件交给前端。

## 数据与验证

- 复用纯函数的 `before`、`after` 相对移动能力，不改变任务状态及扩展字段。
- 继续以 `parentId + position` 表达树结构，并在移动后统一归一化同级位置。
- 组件测试覆盖手柄常显、上半区向前排序、下半区向后排序、拖动结束后提示清理和持久化调用。
- 配置测试覆盖窗口显式设置 `dragDropEnabled: false`。
- 真实浏览器验收覆盖拖动后 DOM 顺序变化；桌面壳使用独立 bundle identifier、临时 HOME 和测试数据库验证 DOM 与 SQLite 顺序变化，避免操作用户现有任务数据。
